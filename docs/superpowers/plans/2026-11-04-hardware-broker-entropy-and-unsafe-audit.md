# Hardware Broker, Entropy & Unsafe TCB Audit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement a secure kernel PCI/hardware configuration broker (Syscall 29 `DeviceIo`), generate authentic cryptographic `AT_RANDOM` entropy vectors, eliminate privileged I/O instructions from Ring 3 drivers, and audit the kernel's `unsafe` surface with explicit `// SAFETY:` contracts (remediating audit items C-03, S-02, S-01).

**Architecture:** Introduce `SyscallNumber::DeviceIo = 29` in `jambo-abi` allowing authorized Ring 3 drivers (`blockd`, `netd`) to query and configure PCI devices via the kernel broker while non-authorized processes receive `PermissionDenied`. Replace static 16-byte dummy `AT_RANDOM` values in `process.rs` with high-entropy bytes generated by `rdrand` and cycle-counter jitter. Audit and document all kernel `unsafe` blocks with rigorous safety contracts.

**Tech Stack:** Rust 2021 `#![no_std]`, `#![no_main]`, x86_64 port I/O, `rdrand` / `rdtsc` / `cntvct_el0`, SplitMix64, Limine bootloader, QEMU.

**Spec:** `docs/superpowers/specs/2026-11-04-hardware-broker-entropy-and-unsafe-audit.md`

## Global Constraints

- Pure `#![no_std]` and `#![no_main]`. Zero raw `in` or `out` port I/O in Ring 3 userspace binaries.
- All hardware configuration requests from Ring 3 must be validated against caller process capabilities and register bounds.
- `AT_RANDOM` must never be a static or deterministic sequence across reboots or process spawns.
- Every `unsafe` block in the kernel must have a preceding `// SAFETY:` comment explaining invariants and preconditions.
- Format all code with `cargo fmt --all` and verify with `cargo fmt --all -- --check` before committing.
